# 📦 Engine Life Cycle & Workflow

## 0. 전체적인 아키텍처 구조

엔진은 크게 3개의 계층으로 작동된다.

```text
Application (EditorApp / RuntimeApp)
  └─ Engine (Singleton)
       └─ Subsystems (자동 등록 및 위상 정렬 기반 관리)
```

1. **Application 계층:** `main()` 진입점. Editor로 띄울지, 런타임 게임으로 띄울지 결정. (빌드 프로젝트가 다름. EditorApp/RuntimeApp)
2. **Engine 계층:** 싱글톤 엔진 객체. Subsystem들을 관리하고 Update Loop를 담당
3. **Subsystems 계층:** 실제 로직이 돌아가는 모듈들 (Job, ECS, Asset, Graphics 등).

---

## 1. Bootstrapping (초기화 및 부팅)

프로그램이 시작되었을 때 Subsystem들을 어떻게 메모리에 올리고, 의존성대로 초기화를 하게 된다.

### 1.1. Entry Point

- `Launch.cpp`의 `int main(int argc, char* argv[])`에서 시작.
- 목적에 맞는 Application 인스턴스(`EditorApp` or `RuntimeApp`)를 생성하고 `Run()` 호출.
- 이후 `PreInitialize()` -> `RegisterSubsystems()` -> `InitializeEngine()` -> `PostInitialize()`를 거쳐서 `MainLoop`에 진입.

### 1.2. Subsystem Registration & Initialization

가장 중요하게 기억해야 할 핵심: **의존성 기반 자동 초기화 (Topological Sort)**

- 각 Subsystem의 `.cpp`파일에는 `SE_REGISTER_SUBSYSTEM(MySubsystem)`매크로가 선언되어 있다.
- 또한, `.DependsOn<Dep1, Dep2>()`를 통해서 자신이 다른 Subsystem보다 나중에 초기화 되어 하는지를 정의할 수 있다.
- `RegisterSubsystems()`단계에서, 실제로 Engine에 Subsystem이 등록된다.
- `InitializeEngine()`단계에서 `Engine`은 이 종속성 그래프를 읽고 **위상 정렬(Topological Sort)** 을 수행하여, 순서대로 Subsystem들의 `Initialize()`를 호출하게 된다.

### 1.3. Engine Initialize

- Engine 생성자에서 `TypeRegistry`의 Interface Cache구축 및 `VFS::Mount`를 호출
- 이후 `InitializeEngine()` 단계에서 아래와 같은 일을 담당
	- SDL 코어 시스템 초기화
	- `JobSystem`과 `AsyncFileIO`초기화
	- Subsystem을 의존성에 따라 정렬 후 초기화

## 3. Render Frame (렌더링 파이프라인 연동)

로직이 완전히 끝나면 `RenderSubsystem`에서 프레임을 화면에 그리게 된다. (Render Graph 기반)

1. **`Setup` Phase (자원 선언):**
   - 각 Render Pass (`RenderPassBase` 상속)들이 자신이 필요한 가상 자원(Texture, Buffer)을 선언하고 Read/Write 의존성을 `RenderGraphBuilder`에 등록.
   - 이후 `RenderGraph.Compile()`에서 아래와 같은 일을 담당하게 된다.
	   - 이번 프레임에서 사용할 리소스 할당
	   - 사용하지 않는 Pass를 Culling
	   - 각 Pass간 실행 의존성 정렬
	   - 리소스의 생명주기를 분석하여 메모리 최적화

2. **`Execute` Phase (커맨드 기록):**
   - `RGExecutionContext`를 통해 실제 SDL3GPU GPU 명령을 기록.
   - 화면에 최종 Present(Swapchain)

## 4. Shutdown (종료 단계)

- 루프 탈출 조건 충족 시 (OS 닫기 버튼, Editor 종료 이벤트 등) 메인 루프를 빠져나옴.
- **초기화 순서의 역순(Reverse Topological Order)**으로 Subsystem의 `Release()`를 호출
- 이후 `Engine`도 `Release()`되며, 메모리 누수 없이 (Job Thread 종료 대기 등) 안전하게 프로세스 종료.
